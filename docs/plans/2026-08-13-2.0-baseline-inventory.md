# Searchable 2.0 Baseline Contract Inventory

## Status

Active — reference document for Slice 1 of the 2.0 simplification plan.

## Purpose

Record the full public surface of Searchable 1.x before deletion begins. Each item is classified as **keep** (retained in 2.0), **remove** (deleted), or **move-internal** (no longer publicly exported but code may remain as an implementation detail).

Cross-reference with [the 2.0 simplification plan](../plans/2026-08-13-searchable-2.0-simplification.md) for rationale.

## 7. Current Performance Baseline

Recorded in `docs/project/performance-baseline.md` and `benchmark-results/cms-2k/reviewed-baseline.json`.

- Corpus: 2,006 docs (1,003 en + 1,003 de)
- Index: 54 files, 51 shards, 13.66 MB raw / 651 KB gzip
- Cold p50: 12.7-24.2ms per query
- Warm p50: 0.2-0.4ms per query

---

## 8. Binary-vs-JSON Evidence

Recorded in `docs/archive/investigations/binary-vs-json-index.md` and `benchmark-results/structured-binary-doc-store/README.md`.

Key finding: Directory-based lazy binary decode was 2-9x faster than full JSON parse for term shards, but at the cost of a custom codec. JSON-only is the 2.0 simplification choice; performance will be addressed by index optimization (shard sizing, compression, caching) rather than binary codecs.
